# Domain Docs

Single-context repo: `CONTEXT.md` at the root is the glossary, `docs/adr/` holds the decisions.

Before you explore the codebase, read `CONTEXT.md` and the ADRs that touch your area. If a file does not exist, proceed silently. The `/domain-modeling` skill creates them when a term or a decision gets resolved.

Use the glossary terms in your output: issue titles, proposals, test names. If a concept is not in the glossary, note the gap for `/domain-modeling`.

If your output contradicts an ADR, say so instead of overriding it silently.
