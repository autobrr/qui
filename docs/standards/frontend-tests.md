# Frontend test standards

- The rules in `docs/standards/tests.md` apply to frontend tests too, except the Go ones. For example, a test from a bug fix gets `// regression: #N` on the line above it.
- Vitest + React Testing Library. A new test goes in the `__tests__/` folder of the directory it covers (`components/cross-seed/__tests__/`) where that folder exists, else beside the file as `*.test.ts(x)`.
- Prefer extracting logic into hooks (`web/src/hooks/`) and pure helpers (`web/src/lib/`) so it is unit-testable without mounting the whole tree (see `web/src/hooks/torrent-table/` for the pattern).
- Vitest runs with `globals: false` + jsdom. The setup file `web/src/test/setup.ts` runs the MSW server lifecycle, gives jsdom a `localStorage` when Node has none and a `ResizeObserver` that does nothing, and unmounts each render after each test. `web/vitest.config.ts` restores each `vi.spyOn`, `vi.stubGlobal`, and `vi.stubEnv` before each test, and runs the suite in UTC:
  - Import test globals explicitly: `import { afterEach, describe, it, expect, vi } from "vitest"`; use `render` / `renderHook` / `act` / `cleanup` from `@testing-library/react`.
  - A test needs no teardown for those. Stub a global in `beforeEach` or in the test, not at the top of the file, because the restore before each test removes a stub from the top of the file. Call `cleanup()` or `unmount()` yourself only between two `render` calls inside the same test. A test of another time zone sets it with `vi.stubEnv("TZ", ...)`.
  - No jest-dom matchers (`toBeInTheDocument`, `toHaveTextContent`, …) — assert plain DOM: `el.textContent`, `el.getAttribute(...)`, `expect(node).toBeNull()`.
  - When mounting components with effects, mock their boundaries (`@/lib/api`, router, context providers, `useVirtualizer`, query hooks) and return a **stable singleton** from each mock — fresh objects per render loop effects and OOM the worker. Use `vi.hoisted()` for values referenced inside `vi.mock` factories.
- A test that asserts translation keys echoes them (`t: (key) => key`, plus any interpolation values it asserts); a test that asserts visible text loads `@/i18n`. No stand-in translator returns the English `defaultValue`. A `react-i18next` mock in a file that loads `@/i18n` spreads `importOriginal`, because `@/i18n` needs the real `initReactI18next`.
- jsdom does no real layout, scroll, or pointer/drag work — it renders **zero virtual rows** and cannot exercise virtualization, dnd-kit, or scroll restoration. Unit-test the extractable logic (reorder math, row-height mapping, handler wiring) and **manually smoke** anything visual or interactive; a green suite is not full coverage.
- Run targeted with `cd web && pnpm exec vitest run <path>`. CI gates for `web/`: `lint.yml` runs eslint on changed files, and only `error` rules fail CI. `lint.yml` also runs `pnpm check:i18n`. `release.yml` runs `pnpm test` and the build (`pnpm run build` type checks with `tsc -b`).
