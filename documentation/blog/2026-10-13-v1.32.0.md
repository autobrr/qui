## Breaking changes
- **Backup history uses a new storage format.** If you plan to go back to an earlier qui after you upgrade, export the backup runs that you need first, because restore fails for every run after a downgrade. Exported archives import on any version.
- **Automation rule JSON is decoded strictly.** A create, update, import, or dry run now returns 400 for an unknown key, a key with the wrong case, or a value of the wrong type. An import with `intervalSeconds` below 60 also fails, so remove these keys from your scripts and saved JSON files.
- **Rule conditions are checked against a field table.** qui now rejects an unknown field or operator and a value that the field does not list, such as `seeding` for a state. To save a changed condition, fix the line that the error names.
- **Group IDs are checked on save.** When you edit a rule, the save fails if `grouping.defaultGroupId`, an action `groupId`, or a score rule names a group that does not exist, or a built-in ID with different capitals. Change the ID to an existing group in Edit as JSON.

## Highlights
- **Automation rules that say what is wrong.** qui lists each mistake in a rule with its JSON path, so a typo no longer saves a rule that never matches.
- **Byte and speed units in your language.** Units, decimal separators, and bit rates follow the interface language, for example `1,5 Gio` in French.
- **Lighter backups.** Each backup stores only the torrents that changed, so backups write about 53x less WAL on Postgres.
- **Update guidance for every setup.** **Install update** shows on every setup, and the dialog explains why automatic installation is unavailable and gives manual steps.
- **Hardlink and cross-seed fixes.** Delete rules on `HARDLINK_SCOPE_CROSS` now delete the matching torrents, and season-less batches cross-seed against tracker names with a year.
- **Fixes and polish.** Row actions stay in view in wide tables, a license portal link at the activation limit, correct size labels on the backups page, fewer cached search warnings in the log, and a release notes page in the docs.
